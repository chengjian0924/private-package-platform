登录与账号

用途：进入控制台，管理自己的登录状态与口令。

入口：浏览器打开控制台地址（如 http://<host>:3000/）。

  1. 输入管理员分配的用户名和密码，点「登录」。
  2. 首次登录或密码被重置后会强制弹出改密窗口，此时无需原密码，填两次新密码保存后才能进入。未完成改密前，所有业务接口返回 AUTH_PASSWORD_CHANGE_REQUIRED。
  3. 日常自助改密：点侧栏底部锁形图标，必须填写原密码。改密后其它设备上的会话立即失效。
  4. 退出：点侧栏底部退出图标，当前会话吊销。

注意：口令长度由服务端配置决定，不能包含用户名，也不能是弱口令。连续输错会临时锁定（默认 5 次 / 15 分钟，以实际配置为准）。忘记密码请联系管理员重置。侧栏只显示你有权限的模块，看不到某个入口说明当前角色未授权。

安装私有包

用途：在项目里用 npm / pip 从私有源安装已入库的包。

入口：项目终端。下载包无需登录或令牌，配置好源地址即可。下例 <host>:3000 换成实际部署地址；拆分端口部署时以管理员提供的地址为准。

npm —— 安装

# 一次性设置私有源
npm config set registry http://<host>:3000/npm/

# 在项目里安装
npm install <package>

预期：提示 added N packages；package-lock.json 中该包的 resolved 地址指向私有源。

pip —— 安装

pip install --index-url http://<host>:3000/pypi/simple/ --trusted-host <host> <package>

预期：终端显示从私有源下载并成功安装。若部署了 HTTPS 网关，可去掉 --trusted-host。

注意：--trusted-host 仅用于内网 HTTP 源。仓库支持 wheel 与 sdist，Python 运行时兼容性由 pip 在客户端判定。

发布包（需发布权限）

入口：项目终端，包目录下执行；命令行的账号密码与控制台相同。

# npm：先登录，再发布（package.json 需有 name + version）
npm login --registry http://<host>:3000/npm/
npm publish

# PyPI：先打包到 dist/，再上传（按提示输入账号密码）
twine upload --repository-url http://<host>:3000/pypi/ dist/*

预期：login 提示 Logged in；publish / upload 返回版本信息，包立即出现在「包管理」。未通过安全校验时返回 SEC_BLOCKED / SEC_QUARANTINED。

注意：脚本/CI 场景可用访问令牌代替密码，创建与吊销方法见「访问令牌」章节。

包管理

用途：查找已入库的包、下载包文件、查看版本状态。

入口：侧栏「包管理」。

  1. 在搜索框按包名关键字过滤；用「全部生态」下拉切换 npm / PyPI；点「重置筛选」清空条件。
  2. 包按名称分组，点分组行展开版本列表。每行显示版本、文件、大小、架构、Python/Node 版本、上传人、安全结论与下载入口。
  3. 点该行的「下载」获取包文件。只有状态正常的版本提供下载，已隔离和已删除的版本不可下载。
  4. 勾选「含已删除」可查看已删除版本的记录。已删除版本对所有人生效下架，无法安装。

预期：搜索即时刷新列表；展开分组才按需加载版本。列表为空时显示空态提示，不会白屏。

校验详情：版本行的「校验详情」按钮可查看该版本最近一次六维扫描结论与 JSON / CSV 报告。

删除与恢复：你上传的版本在展开行提供「删除」；勾选「含已删除」后可对已删除版本点「恢复」。删除是版本级的，不影响同包的其它版本。

批量导入

两步：上传包文件自动识别 → 全量校验 & 入库。支持 .tgz / .whl / .tar.gz / .zip（zip 自动解压），可多选，单文件上限 200 MB。系统从文件名与包内元数据识别包名和版本。

  1. 点「上传包文件」卡片中的虚线框选择或拖入包文件，点「上传并自动识别」。顶部显示批次号，结果区列出识别出的包名、版本与生态。
  2. 在「全量校验&入库」卡片选择入库模式：partial（跳过失败项，默认）或 strict（有失败即整批中止）。
  3. 点「开始校验」，表格逐条显示校验结果。校验覆盖：文件完整性/SHA256、版本号合法性（npm semver / PyPI PEP 440）、重复版本、运行时目标提示；依赖声明只做透传，不判定跨包兼容性（由下游客户端安装时按需解析）。
  4. 核对无误后点「批量入库」，成功后提示入库数量，可在「包管理」检索到；点「下载报告」获取 CSV 逐条结果。

预期：识别后预览区给出包数与新增版本数；校验失败项显示具体原因码；strict 模式存在失败项时整批拒绝并返回 BATCH_HAS_BLOCKING_ITEMS。

漏洞扫描关闭时批量导入走快速通道：只做基础校验并直接入库，界面文案变为「上传并直接入库」。

缺失依赖

用途：查看构建脚本上报的缺失依赖，了解哪些包还缺、缺在哪些项目。

入口：侧栏「缺失依赖」。平台按「生态 + 包名 + 版本区间」去重，重复上报只累加命中次数。

  1. 用「状态」（待补充 / 已解决）和「生态」下拉过滤记录。
  2. 列表可查看包名、生态、版本区间、上报项目、命中次数、状态与最近上报时间。
  3. 需要补包但当前账号没有补包权限时，把包名和版本区间提供给有权限的同事处理。

预期：过滤即时生效；无匹配记录时显示空态提示。

自助补包（需补包权限）

  1. 在「待补充」记录右侧点「补充此包」，弹窗中确认包名、按需填版本（PyPI 可填 requires_python），选择包文件后提交。
  2. 平台自动执行完整性/兼容性校验与六维安全扫描，通过后入库并把记录置为「已解决」。

预期：记录状态变为「已解决」；校验失败或重复补包返回明确错误（如 MISSING_STATE_INVALID），弹窗保持打开可修正重试。

上报缺失依赖（需导入权限）

在构建脚本中调用接口上报，令牌创建方法见「访问令牌」章节。

curl -X POST http://<host>:3000/api/v1/dependency-reports \
  -H 'Authorization: Bearer yj_xxx' -H 'Content-Type: application/json' \
  -d '{"projectId":"order-service","ecosystem":"npm",
       "dependencies":[{"name":"internal-sdk","versionSpec":"^2.0.0"}]}'

预期：返回成功；同一依赖重复上报只累加 hits，不产生新记录。

安全校验

所有入库路径（npm publish、twine、批量导入、补包）在写入前统一经过六维扫描，未通过不会进入私有源。维度：完整性、恶意代码、已知漏洞、权限风险、敏感信息、行为风险。证据落库前脱敏。

最高风险处置表现与后续
criticalBLOCK 拦截上传失败，返回 SEC_BLOCKED 与 scanId，包不入库
highQUARANTINE 隔离返回 SEC_QUARANTINED，进入隔离区等管理员复核
mediumWARN 告警允许入库，控制台记录风险提示
low / 无ALLOW 通过正常入库，生成校验记录与报告
  1. 查看结果：进入「安全校验」，顶部概览卡显示各处置数量；「校验记录」支持按包名精确筛选、按生态与处置过滤，点行尾按钮查看六维详情与 JSON / CSV 报告。
  2. 隔离区复核（管理员）：在「隔离区待复核」点详情核对风险明细，确认可信后「放行」写回私有源，否则「废弃」清理文件。所有动作写审计。
  3. 导入漏洞库（管理员）：在「漏洞库同步」选择 JSON 快照（顶层数组或 {"advisories":[...]}），点「导入漏洞库」。每条必须含 source / advisoryId / ecosystem / packageName / affectedRange / severity，还可带 title / fixedVersion / references / publishedAt；ecosystem 只能是 npm / pypi / *（跨生态）。同一 advisoryId 覆盖更新，单文件 ≤ 50 MB，导入结果列出 imported / updated / skipped 与跳过原因。
  4. 看库状态：漏洞库卡上半部分是两块统计磁贴（最近导入 / 覆盖生态），下方是严重级别分布条形图——排查「这个包为什么从不命中漏洞」，先看库里有没有对应生态与档位的条目。
  5. 导入后点「立即全量复检」对存量包回溯扫描；命中隔离阈值的版本自动置为隔离。服务端也按配置间隔自动复检。

预期：导入结果展示 imported/updated/skipped 及跳过原因；空漏洞库时给 WARN 提示而非静默放行，不会阻断入库（除非显式开启强制漏洞库）。「隔离区待复核」与「漏洞库同步」两张卡片始终等高，底部各有一条分隔线。

审计日志

用途：追溯导入、补包、登录等全流程操作记录。

入口：侧栏「审计日志」。

  1. 按动作关键字（如 import.batch.commit）、Token 名、结果（success / failure）过滤。
  2. 列表显示时间、操作人、Token、动作、资源、结果与 traceId；结果列成功绿、失败红。点「导出 CSV」下载当前筛选结果。
  3. 日志按 prev_hash → hash 组成哈希链，敏感字段脱敏；把 traceId 提供给管理员可关联服务端日志定位同一请求。

用户管理与机器账号

用途：创建人员账号与 CI 机器账号，分配角色、启停与重置凭据。

入口：侧栏「用户管理」。

  1. 「新建账号」填写用户名（3–32 位，字母数字与 ._-）、显示名、邮箱，选择账号类型与角色后创建。人员账号初始口令统一为 123123123，只展示一次，对方首次登录须改密。
  2. 批量建号：点「下载模板」，仅上传 .xlsx；模板前 5 行是填写须知，从第 6 行表头下方开始填写，单次最多 200 行。角色只接受 reader / developer，批量只创建人员账号。
  3. 角色下拉与「禁用 / 启用」按钮都会先弹二次确认：改角色写明会获得或失去哪些权限，禁用写明会话立即失效、令牌暂时不可用但不会作废。取消后控件自动恢复成服务端真实值。
  4. CI 场景选「机器账号」：不设口令、不能登录控制台，创建后自动弹出「签发访问令牌」。之后也可在列表该行点「签发令牌」补发。
  5. 建议一个仓库建一个机器账号，令牌名用仓库路径（如 ci-group-repo）。令牌明文只显示一次，立即写入流水线密文变量。
  6. 列表里机器账号带 CI 标签、凭据列显示「仅令牌」；「重置密码」对它不可用，换令牌即可。
  7. 禁用（临时停用）：该账号所有会话立即失效，令牌同时不可用，但凭据仍保留——重新启用后自动恢复，可随时回滚。管理员账号唯一，不提供禁用、改角色与重置密码。
  8. 吊销令牌（永久断开）：离职、凭据泄露或项目下线时，点该行「吊销令牌」，该账号名下所有令牌立即作废且无法恢复，重新启用账号也不会复活，只能重新签发。凭据列会显示每个账号还有几个未吊销令牌，禁用状态下标为橙色。
  9. 编辑用户手册：在「用户手册」页点「编辑手册」，管理员可修改各章节内容并点「保存修改」；保存后所有登录用户下次进入即可看到。「恢复默认」清除全部修改。服务端会过滤脚本、事件属性与 javascript: 链接。

注意：审计日志按 Token 名筛选，因此令牌命名要能唯一对应项目，否则事后无法归因。

访问令牌

用途：创建供脚本 / CI 调用接口用的凭证。

入口：侧栏「访问令牌」。

  1. 输入名称（如 ci-pipeline），点「生成令牌」，立即复制只显示一次的令牌串。创建页只给当前登录账号签发；管理员要给其他账号（尤其机器账号）签发，到「用户管理」点对应行的「签发令牌」。令牌名建议按仓库命名（如 ci-group-repo），会写入审计日志。
  2. 列表查看名称、创建时间、最近使用与状态；泄露或不再使用时点「吊销」，弹二次确认并写明令牌名后才会执行，使用该令牌的脚本立即失效。已吊销的令牌会标出原因（手动 / 批量 / 管理员），便于事后回溯。
  3. 筛选：可按令牌名过滤，并按状态切「仅有效 / 全部状态 / 已吊销」；默认只看有效令牌，已吊销的留在库里可查但不干扰日常视图。标题右侧显示有效与已吊销的数量。
  4. 可见范围：普通账号只看得到、也只能吊销自己的令牌。管理员额外有「全部账号 / 仅我的」切换，可看到每个令牌的归属账号与账号状态，并代吊销任意账号的令牌——用于离职清理、凭据泄露处置。代吊销同样不可恢复，审计里会记下目标账号。

注意：令牌仅在创建时展示一次，服务端只存哈希，丢失只能重新生成。安装私有包不需要令牌。

常见问题

现象 / 错误码原因处理
AUTH_INVALID_CREDENTIALS用户名或密码错误核对输入；看提示里的剩余尝试次数
AUTH_ACCOUNT_LOCKED连续输错锁定等待锁定结束或联系管理员重置密码

npm install 报 404 / 找不到包registry 未指向私有源，或包名、版本不存在用 npm config get registry 核对地址；在「包管理」确认包与版本存在
pip 报 SSL / 证书错误内网 HTTP 源未信任加 --trusted-host <host>，或按部署配置内网 CA
507 写入失败磁盘达到只读阈值联系管理员清理存储空间后自动恢复
PKG_VERSION_DUPLICATE同包同版本已入库升级版本号，或删除旧版本后再传
PKG_FILE_UNMATCHED文件名与清单 file 字段不符核对文件名（支持 dist/ 等路径前缀）
TARGET_UNDECLAREDJSON 清单缺 targets补 targets.node / targets.python
SEC_BLOCKED / SEC_QUARANTINED安全校验命中严重/高危按返回 scanId 查看详情与整改建议；隔离包联系管理员复核
SEC_SCAN_BUSY扫描队列已满（上限 50）稍后重试，避免并发上传过多
npm login 成功但 publish 401.npmrc 的 _auth 未用令牌重新 npm login，或手工填「用户名:令牌」的 base64
BATCH_HAS_BLOCKING_ITEMSstrict 模式下存在校验失败项修正失败项后重新校验，或改用 partial 模式

所有失败响应都带可读 message 与 traceId；控制台以 [CODE] message（traceId: ...） 提示。排查时把 traceId 提供给管理员，可在服务端日志中检索同一链路。
