## 1. 文档说明

### 1.1 目的

把前序多轮确认的需求、决策与模块设计合并为一份可评审文档，作为开发排期、接口联调与验收的依据。

### 1.2 范围

| 模块 | 范围 | 不在本版范围 |
|---|---|---|
| A1 | 清单批量导入、全量校验、入库、缺失依赖检测、员工补包、全流程审计 | 公网代理缓存、依赖漏洞扫描 |
| A2 | 管理员建号、本地账号登录、首登强制改密、失败锁定、全局登出、RBAC 鉴权 | 多 IdP 联邦、MFA 自研（v1.0 原范围 OIDC 对接/用户同步已废弃） |
| A4 | 证书签发能力裁剪、埋点保留、扩展预留、回归 | 证书签发功能的重新实现 |

两个私有源（npm registry、PyPI index）本身按需求已确定建设，本文件只定义与 A1/A2/A4 相关的设计与边界；包管理后台的常规增删改查不在本文件展开。

### 1.3 术语

| 术语 | 含义 |
|---|---|
| 清单文件 | 描述待导入包集合的文件（JSON / CSV / requirements.txt） |
| 批次（Batch） | 一次清单导入的完整生命周期载体 |
| 条目（Item） | 批次中的单个「包名 + 版本 + 文件」 |
| PDP | 权限决策点，本设计中即 auth 服务的鉴权接口 |
| 内容寻址存储 | 以文件 sha256 作为对象路径的存储方式 |
| 降级 | 依赖的认证/鉴权服务不可用时的受限运行策略 |

### 1.4 已确认决策

| 编号 | 决策 | 结论 |
|---|---|---|
| C1 | 批量入库模式 | 默认 `partial`（逐包提交），`strict` 为可选显式模式 |
| C2 | 运行时版本校验 | S5 必须校验；`targets` 为清单必填项，缺失即阻断 |
| C3 | 鉴权决策缓存 | 允许短 TTL（默认 5s），敏感动作不走缓存 |
| C4 | A4 裁剪方式 | 保留空模块与数据库表，以开关关闭 + 只读方式停用 |

### 1.5 前提假设

| 编号 | 假设 | 不成立时的影响 |
|---|---|---|
| A1 | 内网完全无公网出口 | 若存在摆渡通道，可增加离线包导入能力 |
| A2 | 两套服务独立运行，经统一入口暴露 | 统一入口是全局登录态与无缝跳转的前提 |
| A3 | 统一域名长期稳定（如 `*.corp.local`） | 域名变更会导致 lockfile 中地址失效 |
| A4 | 使用内网 CA 证书，客户端已信任 | 自签证书需逐台下发 |
| A5 | 服务器为 Linux（x86_64 或 ARM64） | Windows 服务端会收窄选型 |
| A6 | 容量口径：≤500 人、≤5 万版本、≤2TB | 影响性能与备份指标取值 |
| A7 | 「长期稳定」= 单节点 + 备份 + 可恢复 | 若要求 99.9%，需追加 HA 设计 |
| A8 | CI 构建机同样无公网，仅可访问私有源 | 若 CI 可出网，需额外做禁止回源策略 |

## 2. 总体架构

### 2.1 部署视图

```
                 ┌──────────────────────────────┐
   浏览器/CLI ───▶│  gateway（统一入口，会话终结） │
                 └───────┬──────────┬───────────┘
                         │          │
             ┌───────────▼──┐   ┌───▼───────────┐
             │ registry-npm │   │ registry-pypi │
             └───────┬──────┘   └───┬───────────┘
                     │              │
        ┌────────────▼──────────────▼────────────┐
        │  core：领域服务 / 校验 / 审计 / 存储适配  │
        └───────┬───────────────┬────────────────┘
                │               │
        ┌───────▼──────┐  ┌─────▼──────┐   ┌────────────────────┐
        │ SQLite DB    │  │ 对象存储目录 │   │ auth（本地账号+PDP）│
        └──────────────┘  └────────────┘   └─────────┬──────────┘
                                                     │
                                          ┌──────────▼─────────┐
                                          │ users / sessions 表 │
                                          └────────────────────┘
```

### 2.2 模块职责

| 模块 | 职责 | 关键约束 |
|---|---|---|
| gateway | 路由分流（`/api` `/npm` `/pypi` `/auth`）、会话终结、限流 | 不承载业务逻辑 |
| auth | 本地账号认证（口令校验）、会话中心、用户管理、权限决策点 | 唯一鉴权事实源 |
| registry-npm | npm registry 协议（packument、tarball、publish） | 不做本地权限判断 |
| registry-pypi | PEP 503 simple index、legacy 上传协议 | 不做本地权限判断 |
| worker | 校验、入库、缺失检测、对账、审计归档 | 可水平扩展，任务幂等 |

### 2.3 技术约束

- 离线环境不引入 Redis：会话、队列（pg-boss）、缓存均落 PostgreSQL 或进程内。
- 对象存储采用本地文件系统 + 内容寻址，后续可替换为 S3 兼容实现，通过 `storage` 适配层隔离。
- 所有对外接口基于 OpenAPI 3.1 生成，评审以契约文件为准。

### 3.2 存储与一致性

1. 文件写入：临时目录 → 计算 sha256 → 复核 → `fsync` → 原子 `rename` 至 `objects/<sha256[0:2]>/<sha256>`。
2. 元数据与文件引用在同一事务内提交；唯一约束兜底并发。
3. 提交成功后发 `package.published` 事件，触发索引刷新与缓存失效。
4. 每日对账：清理无 DB 引用且超过 TTL 的对象；校验 DB 引用对象是否存在且哈希一致。

## 4. A1 批量导入与缺失补包

### 4.1 能力概览

| 能力 | 入口 | 产物 |
|---|---|---|
| 清单上传与预览 | Web | 批次 + 解析预览 |
| 包文件上传 | Web（多文件 / zip bundle） | 文件匹配结果 |
| 全量校验 | Web / API | 校验报告（JSON/CSV） |
| 批量入库 | Web / API | 包版本记录 + 审计 |
| 缺失依赖检测 | registry 404 / CI 上报 | 缺失事件 |
| 员工补包 | Web | 单包入库 + 事件关闭 |

### 4.2 清单格式

**规范 JSON（v1）**

```json
{
  "schemaVersion": "1.0",
  "ecosystem": "npm",
  "targets": {
    "node": "20.11.0",
    "python": "3.11.9",
    "os": "linux",
    "arch": "x64",
    "libc": "glibc-2.28"
  },
  "items": [
    {
      "name": "lodash",
      "version": "4.17.21",
      "file": "pkg/lodash-4.17.21.tgz",
      "sha256": "<64位十六进制>",
      "optional": false
    }
  ]
}
```

**CSV**：表头固定 `ecosystem,name,version,file,sha256`；`sha256` 为空时按文件实算。

**requirements.txt**：仅 PyPI，解析 `name==version` 与 `--hash=sha256:...`；`-e`、`-r`、通配符、URL 依赖一律标记 `MANIFEST_REQUIREMENT_UNSUPPORTED`，不静默忽略。

**通用解析规则**

| 项 | 规则 |
|---|---|
| 编码 | UTF-8（兼容 BOM），其他编码报 `MANIFEST_ENCODING_INVALID` |
| 大小上限 | 清单 10MB；条目数默认 5000（可配） |
| 必填字段 | `schemaVersion`、`ecosystem`、`targets`、`items[].name/version/file` |
| 重复条目 | 归一化后同名同版本视为重复，报 `MANIFEST_DUPLICATE_ITEM` |
| 未知字段 | 告警，不阻断 |
| targets 缺失 | 批次级阻断，报 `TARGET_UNDECLARED` |

### 4.5 校验流水线

顺序执行，单段失败不短路后续段（便于一次性给出全部问题）。

| 段 | 校验内容 | 说明 |
|---|---|---|
| S1 文件完整性 | 存在性、大小、魔数、压缩包可解、CRC、路径穿越、符号链接、条目数与解压体积、sha256 一致 | 魔数：tgz/tar.gz 为 gzip，whl 为 zip |
| S2 元数据一致性 | npm 读 `package.json`；PyPI 读 `METADATA`/`PKG-INFO`/`WHEEL`；清单值与包内值一致；必填元信息齐备 | 名称需归一化后比对 |
| S3 版本合法性 | npm 按 SemVer 2.0；PyPI 按 PEP 440；归一化后判重 | `1.0` 与 `1.0.0` 归一化后视为等价 |
| S4 唯一性 | `(ecosystem, normalized_name, normalized_version)` 是否已存在；保留名/scope 校验 | 由 DB 唯一约束兜底并发 |
| S5 依赖与运行时兼容 | 依赖可满足性、区间冲突、循环、深度；npm `engines`/`os`/`cpu`；PyPI `Requires-Python`、wheel 标签、ABI、libc、环境标记 | `targets` 必填，缺失即阻断 |

S5 判定口径：

| 场景 | 判定 |
|---|---|
| `targets` 缺失 | 批次级 `TARGET_UNDECLARED`，退回 `FILES_READY` |
| 依赖无法满足 | `DEP_UNRESOLVED`（ERROR） |
| 同一依赖被要求为不相交区间 | `DEP_VERSION_CONFLICT`（ERROR） |
| 循环依赖 | `DEP_CYCLE`（ERROR） |
| 解析深度超限（默认 50） | `DEP_DEPTH_EXCEEDED`（ERROR） |
| npm `peerDependencies` 冲突 | ERROR（与 npm 安装行为一致） |
| 可选依赖不满足 | WARN |
| 环境标记含未知变量 | WARN，附变量名 |
| sdist 且无兼容 wheel | WARN（需离线编译链） |
| 含原生构建/安装脚本 | WARN |

### 4.6 入库

| 项 | 规则 |
|---|---|
| 默认模式 | `partial`：逐条目独立事务，成功即生效 |
| 可选模式 | `strict`：整批单事务，任一失败全批回滚 |
| 并发 | 默认 4（可配），结果与执行顺序无关 |
| 幂等键 | `(batch_id, item_no, sha256)`；重复提交返回首次结果 |
| 失败重试 | `retryFailed=true` 仅重跑失败项 |
| 批次终态 | 全成功 `COMPLETED`；部分成功 `PARTIAL`；全失败 `FAILED` |
| 孤儿清理 | 未提交成功的对象由每日对账按 TTL 清理 |
| 变更限制 | 进入 `IMPORTING` 后清单不可改，需新建批次 |

`partial` 模式下若 B 依赖同批 A 且 A 失败，报告中 B 的失败需附注「可能受同批其他包影响」。

> **v1.1 变更（2026-11-16，决策 D-14）**：单位暂无统一认证平台，v1.0 的 OIDC 授权码方案整体废弃，现行实现为**本地账号密码**。
>
> | 项 | v1.0 设计 | v1.1 实现 |
> |---|---|---|
> | 身份来源 | 外部 IdP（OIDC） | 平台内 `users` 表，管理员建号 |
> | 口令 | 无（IdP 托管） | scrypt（N=16384/r=8/p=1，参数随哈希保存）+ `timingSafeEqual` 比较 |
> | 登录 | `GET /auth/login` → 302 IdP | `POST /api/v1/auth/login`，成功后 Set-Cookie `yj_sid` |
> | 首登 | 无 | 初始密码 16 位随机、`must_change_password=1`；未改密仅放行 me / 改密 / 权限检查 / 登出，其余返回 `AUTH_PASSWORD_CHANGE_REQUIRED` |
> | 失败防护 | 依赖 IdP | 连续 5 次失败锁定 15 分钟；用户不存在时仍做一次伪造哈希校验，防止用户名枚举 |
> | 会话 | 会话表 + 父域 Cookie | 会话表 + `HttpOnly; SameSite=Lax; Secure`（HTTPS 时） |
> | 登出 | 本地 + back-channel | `ALL /auth/logout` 吊销当前会话；改密吊销该用户其它会话 |
> | 用户同步 | SCIM / 每日对账 | 无外部同步；管理员在「用户管理」中增改、禁用与重置密码 |
> | 出站 | IdP / JWKS | 无认证出站；仅可选内网 SNTP 时钟观测 |
> | 生产护栏 | 禁 mock / 禁本机 issuer | 校验 `BOOTSTRAP_ADMIN_PASSWORD` 强度（≥最小长度、不含用户名、非弱口令） |
>
> 首启建号：用户表为空时用 `BOOTSTRAP_ADMIN_USERNAME` / `BOOTSTRAP_ADMIN_PASSWORD` 创建管理员，建号后必须改密并移除该环境变量。

### 5.1 组件与登录流程

| 角色 | 职责 |
|---|---|
| IdP | 统一认证中心，提供授权、令牌、用户信息、JWKS、登出端点 |
| gateway | 会话终结、Cookie 管理、路由分流、鉴权调用 |
| auth | OIDC 客户端、会话中心、PDP |
| registry-* | 资源服务，仅执行鉴权结果 |

登录流程：

1. 访问 `/npm` 或 `/pypi` 未带有效会话 → gateway 302 至 `/auth/login?return_to=<原始地址>`。
2. auth 生成 `state`、`nonce`、PKCE `code_verifier`，302 至 IdP 授权端点。
3. IdP 回调 `/auth/callback?code=&state=`。
4. auth 校验 `state` 一次性、`nonce`、`code_verifier`，调用令牌端点换取 `id_token` / `access_token`，调用 userinfo 获取身份。
5. 按 `sub` upsert 用户，创建会话，写 Cookie（`HttpOnly; Secure; SameSite=Lax; Domain=.corp.local`）。
6. 302 回 `return_to`（必须在白名单内）。

跨服务免二次登录：同一父域 Cookie + IdP 侧 SSO 会话；会话临近过期时可 `prompt=none` 静默续期。

| 项 | 规则 |
|---|---|
| 主路径 | 每次登录按 `sub` upsert |
| 兜底 | 每日全量对账 + 增量同步（SCIM 或 IdP 事件） |

### 5.5 会话与全局登出

| 项 | 规则 |
|---|---|
| 存储 | `sessions` 表为唯一事实源，各服务不落本地会话副本 |
| Cookie | `HttpOnly; Secure; SameSite=Lax; Domain=.corp.local` |
| 有效期 | 绝对过期（默认 8h）+ 空闲过期（默认 30min），滑动续期限频 |
| 登出 | 吊销本地会话 → 调 IdP 登出 → back-channel 按 `idp_sid` 批量吊销 |
| 时效 | 全局登出生效 ≤5s |
| 会话固定防护 | 登录成功后重新生成 `sid` |

### 5.6 鉴权与缓存

| 项 | 规则 |
|---|---|
| 决策位置 | 全部由 auth 的 PDP 完成，registry 不写权限判断 |
| 缓存 TTL | 默认 5s，可配 1–10s |
| 缓存键 | `hash(subject, action, resource, policyVersion)`，策略用到 IP 时才纳入 |
| 缓存位置 | 进程内 LRU，单实例上限 5 万 |
| 失效 | 角色/权限/绑定变更时 `policyVersion` 自增，命中比对版本 |
| 负向缓存 | 拒绝结果 TTL 2s |
| 不走缓存 | `admin:*`、删除、权限变更、会话吊销 |
| 生效时延 | 权限变更端到端 ≤5s；敏感动作 0s |
| 指标 | 命中率、回源 QPS、`policyVersion` 分布；命中率目标 ≥90% |

### 5.7 异常与降级

| 场景 | 处理 |
|---|---|
| IdP 不可用 | 已登录会话在有效期内继续可用；新登录快速失败并展示明确页面，不回退本地账号 |
| auth 服务不可用 | 缓存未过期继续生效；过期后读操作可在 `authzGraceTTL`（默认 30s，可配 0）内沿用最后决策并打 `degraded=true` 审计；写操作一律 503 |
| 宽限期用尽 | 全部拒绝，禁止降级为匿名可写 |
| token 刷新失败 | 清除会话并跳登录，保留 `return_to` |
| JWKS 获取失败 | 本地缓存 + `kid` 未命中强制刷新一次，仍失败则 fail-closed |
| 时钟偏移 | 允许 60s，超限告警并拒绝 |
| 回调重放 | `state` 一次性、`nonce` 校验、回调限流 |
| 只读降级开关 | 禁止上传、允许拉取，操作留审计 |

### 5.8 状态机

**登录流程**

| 当前状态 | 下一状态 | 条件 |
|---|---|---|
| INITIATED | CALLBACK_RECEIVED | 收到合法 `code` + `state` |
| INITIATED | FAILED | `state` 过期/不匹配 |
| CALLBACK_RECEIVED | VALIDATED | 令牌交换与身份校验成功 |
| CALLBACK_RECEIVED | FAILED | 令牌交换失败、nonce 不符 |
| VALIDATED | ESTABLISHED | 会话创建成功 |
| ESTABLISHED / FAILED | — | 终态 |

**会话（sessions）**

| 当前状态 | 下一状态 | 条件 |
|---|---|---|
| ACTIVE | IDLE_EXPIRED | 超过空闲过期 |
| ACTIVE | EXPIRED | 超过绝对过期 |
| ACTIVE | REVOKED | 登出 / back-channel / 管理员吊销 |
| IDLE_EXPIRED / EXPIRED | ACTIVE | 滑动续期成功（仅当未超绝对过期且未吊销） |
| REVOKED | — | 终态 |

## 6. A4 证书能力裁剪

### 6.1 裁剪范围

| 层 | 移除对象 |
|---|---|
| 前端 | 证书相关路由、菜单、页面组件、表单、i18n 文案键、按钮权限绑定 |
| 接口 | 签发/续期/吊销/查询的 controller 与 OpenAPI 路径 |
| 业务 | 签发编排、CA 调用、密钥生成与存储、CSR 处理、证书分发与下载 |
| 任务 | 到期提醒、自动续期、吊销同步等定时任务与队列消费者 |
| 配置 | CA 地址、证书模板、密钥库路径等配置项与密钥引用 |
| 权限 | `cert:*` 权限码与角色绑定（保留表结构，删除前先备份） |

执行顺序：关闭开关并回归 → 物理删除代码 → 清理配置与权限。数据库表不删。

### 6.2 保留物

| 保留项 | 内容 | 约束 |
|---|---|---|
| 模块骨架 | `certificates/certificate.module.ts` | 仅声明模块，无 provider，不被 `AppModule` 导入 |
| 端口接口 | `certificates/ports/certificate-issuer.port.ts` | 仅类型定义，无实现 |
| 事件契约 | 四个事件名 + Schema | 仅定义，无业务调用点 |
| 埋点能力 | `libs/telemetry` 的 `TelemetryPort` | 保持可用，可手工触发验证 |
| 数据库表 | `certificate_*` 全表与迁移历史 | 标记 deprecated，停止写入，仅 `SELECT` |
| API 命名空间 | `/api/v1/certificates/*` | 410 桩，返回 `X-Feature-Status: disabled` |

写入拦截三重保障：

1. 应用层：模块未导入，无写入路径。
2. 仓储层：若被误引用直接抛 `CERT_FEATURE_DISABLED`。
3. 数据库层：回收应用账号 `INSERT/UPDATE/DELETE` 权限，仅保留 `SELECT`。

### 6.3 埋点契约

| 事件名 | 触发时机（后续迭代） | 必填 payload 字段 |
|---|---|---|
| `cert.issue.started` | 发起签发 | `certType`、`algorithm`、`purpose`、`requestId` |
| `cert.issue.validated` | 校验通过 | `requestId`、`validator`、`durationMs` |
| `cert.issue.completed` | 签发成功 | `requestId`、`serialNumberHash`、`validFrom`、`validTo`、`durationMs` |
| `cert.issue.failed` | 签发失败 | `requestId`、`errorCode`、`stage`、`durationMs` |

统一信封：

```json
{
  "eventName": "cert.issue.completed",
  "schemaVersion": "1.0",
  "traceId": "...",
  "actorId": "...",
  "occurredAt": "2026-11-13T10:00:00Z",
  "payload": {}
}
```

禁止写入：私钥、证书正文、证件号、手机号等敏感信息。事件定义、Schema、看板与告警规则保留；产生事件的全部业务调用点删除。

### 6.4 扩展预留

- 开关 `features.certIssuance=false` 同时控制「模块导入」与「路由挂载」。
- 恢复顺序写入 ADR：开关打开 → 实现 `CertificateIssuerPort` → 注册 provider → 数据回填 → 打开前端入口。
- 字段只增不改不删；后续新建 `certificate_requests` 表，不复用旧表写入。
- `/api/v1/certificates` 命名空间保留，避免前端路径变更。

### 6.5 回归重点

| 项 | 方法 |
|---|---|
| 路由与菜单残留 | 全量爬取，检查死链与 404 菜单 |
| 接口残留 | OpenAPI 契约 diff，仅允许删除证书相关路径 |
| 代码残留 | `knip` / `ts-prune` 扫描未引用导出 |
| 依赖规则 | 业务代码引用证书 service 时 CI 失败 |
| 数据写入 | 对 `certificate_*` 写操作必须被拒绝 |
| 埋点 | 手工触发断言事件结构 |
| 主链路 | 登录、浏览、上传、拉取、审计五条冒烟用例 |
