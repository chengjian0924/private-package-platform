# 核心功能使用指引

本文面向种子用户，按「登录 → 消费 → 发布/导入 → 补包 → 安全校验 → 审计 → 令牌」的顺序说明操作步骤。默认以开发环境 `http://localhost:3000` 为例，测试环境把地址换成 `http://localhost:3100` 即可，操作完全一致。

## 1. 登录与账号

1. 浏览器打开 `http://localhost:3000/`，输入用户名与密码登录。账号由管理员在「用户管理」中创建。
2. 首次登录、或密码被管理员重置后，会弹出不可关闭的改密窗口；此时**不需要输入原密码**，直接设置两次新密码即可。未完成改密前，除 `/api/v1/auth/me`、改密、权限检查与登出外的接口一律返回 `AUTH_PASSWORD_CHANGE_REQUIRED`。
3. 开发/测试环境的初始管理员由 `.env.*` 的 `BOOTSTRAP_ADMIN_USERNAME` / `BOOTSTRAP_ADMIN_PASSWORD` 在首次启动、用户表为空时创建；**生产环境建号后必须立即改密，并把该口令从环境变量中移除**（用户表非空后该变量不再生效）。
4. 口令要求：不少于 `PASSWORD_MIN_LENGTH`（默认 8）位，不能包含用户名，不能是常见弱口令；连续 `LOGIN_MAX_FAILURES`（默认 5）次输错锁定 `LOGIN_LOCK_MINUTES`（默认 15）分钟，锁定期间即使口令正确也无法登录，成功登录后失败计数清零。
5. 忘记密码联系管理员重置，重置后的初始密码只展示一次，且会解除锁定。
6. 登录成功后侧边栏显示当前用户与角色；「修改密码」可随时自助改密（这里必须输入原密码），改密后其它设备上的会话立即失效。
7. 点击「退出登录」吊销当前会话。

侧边栏只展示当前角色有权限的视图；无权限的接口会返回 `AUTH_FORBIDDEN`，不会出现空白页。

## 2. 包管理：检索与下载

- 进入「包管理」，可按包名关键字搜索、按生态（npm / pypi）过滤。
- 列表展示包名、生态、版本数、创建时间；点击包名或「版本详情」查看全部版本。
- 版本行展示文件名、大小、平台架构、兼容 Python / Node 版本、上传人，点击「下载」直接获取包文件；有安全权限的用户可点击「校验详情」查看该版本最近一次扫描结论。
- 删除是**版本级**操作：上传者本人可删除自己的版本，**管理员可代为删除任何人的版本**（代操作会写审计日志）。删除为软删除，版本立即对所有人下架，同包其它版本不受影响。
- 右上角「含已删除」勾选后才能看到已删除版本并恢复：本人可恢复自己的版本，管理员可代为恢复任何人的版本（同样写审计，归属仍是原上传人）。他人看不到你删除的版本，也无法安装。
- 列表为空时展示空态提示，不会出现无响应空白区域。

## 3. 发布与安装

### 3.1 npm

```bash
npm config set registry http://<host>:3000/npm/
npm login --registry http://<host>:3000/npm/     # 用户名 + 真实密码，成功后自动写入 _auth（API Token）
npm publish                                     # 在包目录执行
npm install <package> --registry http://<host>:3000/npm/
```

> 除 `npm login` 外，npm 路由的 Basic 认证只认 API Token（避免每次拉取元数据都做一次口令哈希校验）。若手工配置 `.npmrc`，`_auth` 请填 `用户名:令牌` 的 base64。

控制台「包管理」页顶部提供「npm 接入」按钮，点击可查看当前环境对应的命令。

### 3.2 PyPI

```bash
pip install --index-url http://<host>:3000/pypi/simple/ --trusted-host <host> <package>
twine upload --repository-url http://<host>:3000/pypi/ dist/*
```

支持 wheel 与 sdist；上传时校验文件名与版本号合法性、重复版本、运行时标签（声明 `requires_python` 时）。版本号按 PEP 440 相等语义归一，`1.0` 与 `v1.0` / `1.0.0` 视为同一版本，重复上传会被拒绝。

## 4. 批量导入（管理员）

入口：「批量导入」，按页面步骤条依次操作。

> **当前版本是免清单模式**：直接把 `.tgz` / `.whl` / `.tar.gz`（或一个 `.zip`）拖进「上传包文件」，服务端从包内 `package.json` 或文件名识别出包名与版本，自动建批次；随后仍是「全量校验 → 确认入库」。下面步骤 1–2 的清单解析说明为历史设计留档，界面已不再要求清单文件。
>
> **幂等**：同一批包的内容指纹（文件 sha256 + 包身份 + 运行时目标）相同且上一次批次还没结束时，服务端直接复用那个批次并返回 `deduplicated: true`，页面顶部会提示「内容重复，已复用已有批次」——双击上传、浏览器重发、网络重试都不会重复落盘或重复扫描。若该批次已经校验过，会直接跳到「入库」步骤。文件名和版本相同但文件内容不同（重新打包过）不算重复，会正常新建批次。

### 步骤 1：准备清单文件

支持 `.json`、`.csv`、requirements `.txt` 三种格式，单文件不超过 `MAX_MANIFEST_BYTES`（默认 10 MB），条目不超过 `MAX_ITEMS`（默认 5000）。

JSON（推荐，必须声明 `targets`）：

```json
{
  "schemaVersion": "1.0",
  "ecosystem": "npm",
  "targets": { "node": "20.11.0" },
  "items": [
    { "name": "lodash", "version": "4.17.21", "file": "lodash-4.17.21.tgz", "sha256": "可选" }
  ]
}
```

- `ecosystem` 可为 `npm` / `pypi` / `mixed`；`mixed` 时每个条目需单独写 `ecosystem`。
- npm 条目必须声明 `targets.node`，PyPI 条目必须声明 `targets.python`，否则返回 `TARGET_UNDECLARED`。
- JSON 支持 `optional` 字段与未知字段告警（未知字段会被忽略并在预览中提示）。

CSV（表头固定，`sha256` 可留空）：

```csv
ecosystem,name,version,file,sha256
npm,lodash,4.17.21,lodash-4.17.21.tgz,
pypi,requests,2.32.3,requests-2.32.3-py3-none-any.whl,
```

requirements `.txt`：仅支持 `name==version` 精确固定版本，可选 `--hash=sha256:<64位>`；`-e`、`-r` 等写法会被明确拒绝。CSV 与 requirements 未声明 targets 时，使用服务端默认运行时目标（`DEFAULT_NODE_TARGET` / `DEFAULT_PYTHON_TARGET`）。

### 步骤 2：上传清单并预览

1. 选择生态（仅对 CSV / requirements 生效）。
2. 拖拽或点击选择清单文件，点击「上传并解析」。
3. 预览区展示总条目数、生态分布、新增版本数与已存在版本数，以及解析告警；顶部显示批次号。

解析失败会直接提示具体错误码与原因（如 `MANIFEST_FIELD_MISSING`、`MANIFEST_DUPLICATE_ITEM`、`MANIFEST_FORMAT_INVALID`）。

### 步骤 3：上传包文件

1. 拖拽或选择本次清单对应的包文件，可一次多选；也支持上传一个 `.zip`，由服务端自动解包。
2. 点击「上传包文件」，结果区展示接收文件数、匹配条目数与未匹配条目序号。
3. 文件名需与清单 `file` 字段一致（支持路径前缀，如 `dist/lodash-4.17.21.tgz`）。

### 步骤 4：全量校验与入库

1. 选择入库模式：
   - `partial`（默认）：通过项入库，失败项跳过；
   - `strict`：存在任一失败项则整批拒绝，返回 `BATCH_HAS_BLOCKING_ITEMS`。
2. 点击「开始全量校验」，逐条展示校验结果与失败原因：
   - S1 文件完整性：文件存在、SHA256 匹配、压缩包可读；
   - S2 版本号合法性：npm 遵循 semver，PyPI 遵循 PEP 440（含 `v` 前缀、epoch、pre/post/dev 别名等完整写法）；
   - S3 重复版本：同一包同一版本不可重复入库。PyPI 按 PEP 440 **相等语义**判重，`1` / `1.0` / `1.0.0` / `v1.0` 视为同一个版本，只保留最早入库的一个；文件名与清单版本只需语义等价即可，不要求字符串完全相同；
   - S4 依赖声明：**不做跨包兼容性判定**，依赖字段按白名单原样透传到 packument。私有源只负责存储，由下游 `npm` / `pip` 客户端在安装时按自身需求解析版本；入库时若拿「当前已入库版本集合」去比对依赖区间，会把「依赖包还没导全」误判成消费方不兼容并跳过入库；
   - S5 运行时版本：npm / PyPI 均为**通用仓库**，面向任意运行时版本的包均可入库。npm 的 `engines.node` / `os` / `cpu` 与 PyPI 的 `requires_python` / wheel 标签（python/abi/platform）都只作为元数据记录并给出提示告警，**不阻断入库**；由 `npm` / `pip` 在拉取时按客户端环境自行挑选兼容包。
3. 查看无误后点击「确认入库」，成功后提示入库数量，可在「包管理」中检索到新包。
4. 点击「下载校验报告」获取 CSV 报告，包含每条的状态与原因码，可用于离线复核。

## 5. 缺失依赖与自助补包

### 上报缺失依赖（CI / 构建脚本）

```bash
curl -X POST http://<host>:3000/api/v1/dependency-reports \
  -H 'Authorization: Bearer yj_xxx' \
  -H 'Content-Type: application/json' \
  -d '{
    "projectId": "order-service",
    "ecosystem": "npm",
    "dependencies": [{ "name": "internal-sdk", "versionSpec": "^2.0.0" }]
  }'
```

平台按「生态 + 包名 + 版本区间 + 项目」去重：重复上报只累加命中次数（`hits`），不会产生重复记录。**本地已有 active 版本的包会自动跳过**（响应里的 `skipped` 字段给出数量），因此直接上报项目完整依赖清单也不会污染缺失列表。仓库内 `scripts/ci-report-missing.mjs` 是零依赖的比对脚本，可在上报端先探测私有源只推差集，接入方式见 [MISSING_REPORT_CI.md](MISSING_REPORT_CI.md)。

### 拉取失败自动上报（零配置兜底）

下游项目把本平台配成 npm / PyPI 源后，**无需改任何代码**：当 `npm install` / `pip install` 拉不到包（registry 返回 404），平台自动登记一条缺失依赖。

- 按「生态 + 包名 + 版本要求」聚合，重复失败只累加 `hits`，记录最后一次请求的来源 IP 与 User-Agent。
- 能从下载路径解析出版本时（npm tarball、PyPI wheel/sdist）记具体版本；只有包名时记 `*`。
- 带鉴权头的 404 会标注，便于区分「真缺包」和「私有 scope 无权限」。
- 该路径完全静默：上报失败绝不影响客户端收到的 404 响应；显式上报接口 (`dependency-reports`) 不受开关影响。

在「字典管理 → 缺包自动上报」可随时关闭，默认开启。关闭只停止新增，已有记录保留。缺失依赖列表按命中次数排序，可按来源筛选（自动上报 / 项目上报；「批量导入」仅用于历史记录）。缺失依赖以真实拉取失败（404）为准，批量导入不再推测登记。

### 补包

1. 进入「缺失依赖」，按状态（待补充 / 已解决）与生态过滤。
2. 在待补充记录右侧点击「补充此包」，弹窗中确认包名，按需填写版本号（PyPI 还可填 `Requires-Python`），选择包文件后提交。
3. 平台自动执行与批量导入相同的完整性/兼容性校验，校验通过后直接入库，并把该缺失记录置为「已解决」。
4. 校验失败或记录已解决时返回明确错误（如 `MISSING_STATE_INVALID`），弹窗保持打开，可修正后重试。

## 6. 安全校验

所有上传入口（npm publish、twine upload、批量导入、缺失依赖补包）在包入库前都会自动执行一次全量安全校验，**通过前不会进入私有源**。控制台「安全校验」页（仅 admin 可见）用于查看结果、复核隔离包与同步漏洞库。

### 6.1 六维校验结果

| 维度 | 关注点 |
| --- | --- |
| 格式与完整性 | 文件头与扩展名是否一致、归档是否损坏、是否含路径穿越/重复条目/嵌套归档、签名是否有效 |
| 恶意代码 | 反弹 Shell、编码载荷执行、挖矿、下载即执行、破坏性删除、读取凭据、提权、持久化等 |
| 已知漏洞 | 包自身版本与依赖声明命中本地 CVE / CNVD / OSV 漏洞库的情况 |
| 权限风险 | 安装脚本、setuid、`.pth` 注入、`setup.py` 安装期逻辑、容器高权限、可执行文件等 |
| 敏感信息 | 私钥、云厂商密钥、平台令牌、硬编码口令、JWT、连接串、手机号/身份证、内网 IP |
| 行为风险 | 未声明的网络外联、敏感文件读取后外联、写系统路径、动态加载、原生二进制等 |

### 6.2 分级处置

| 最高风险 | 处置 | 用户侧表现 |
| --- | --- | --- |
| 严重（critical） | 拦截 | 上传失败，返回 `SEC_BLOCKED` 与 `scanId`，包不入库 |
| 高危（high） | 隔离 | 上传失败，返回 `SEC_QUARANTINED` 与 `scanId`，包进入隔离区等待管理员复核 |
| 中危（medium） | 告警 | 上传成功，记录风险并在控制台展示 WARN |
| 低危 / 无风险 | 通过 | 上传成功，生成合格校验记录与报告 |

阈值由服务端 `SECURITY_BLOCK_SEVERITY` / `SECURITY_QUARANTINE_SEVERITY` 控制；签名校验可选，未提供签名不阻断。

### 6.3 查看校验记录与报告

1. 进入「安全校验」，顶部卡片展示通过、告警、待复核隔离、已拦截数量与漏洞库条目数。
2. 「校验记录」支持按包名精确筛选、按生态与处置过滤；每行展示时间、包名@版本、结论、处置、风险分、签名状态与触发方式（上传 / 复检）。
3. 点击「详情」查看：
   - 六维校验结果与每维摘要；
   - 逐条风险明细（规则编号、等级、位置、脱敏证据、整改建议）；
   - sha256、traceId、耗时等可追溯信息；
   - 「下载 JSON 报告」「下载 CSV 报告」。
4. 若上传时被拦截或隔离，把返回的 `scanId` 提供给管理员，可在「校验记录」中定位同类问题并获取整改建议。

### 6.4 隔离区复核（管理员）

1. 在「隔离区待复核」中查看被隔离的包与版本。
2. 点击「详情」核对风险明细与整改建议；确认业务可信后可点击「放行」，包会重新写入私有源并可被安装。
3. 点击「废弃」将清理隔离文件；若为存量版本复检隔离，放行恢复可用，废弃则软删除。
4. 所有放行/废弃动作写入审计日志，记录操作人与时间。

### 6.5 漏洞库同步与定期复检（管理员）

1. 在「漏洞库同步」中选择 JSON 快照并点击「导入漏洞库」。支持顶层数组或 `{ "advisories": [...] }`，必填字段为 `source`、`advisoryId`、`ecosystem`、`packageName`、`affectedRange`、`severity`；可选字段包括 `title`、`fixedVersion`、`references`、`publishedAt`。其中 **`ecosystem` 必填**，只能是 `npm` / `pypi` / `*`；缺失或写成其它家族会被跳过，导入结果里会列出被跳过的条目和原因。同一 `advisoryId` 覆盖更新，单文件 ≤ 50 MB。`*` 表示跨生态条目，npm 与 PyPI 扫描都会命中，漏洞库列表中以「跨生态」标签标出。
2. 卡片上半部分展示库状态：左侧「最近导入」（时间、来源、条数、操作人），右侧「覆盖生态」（npm / PyPI / 跨生态各多少条）；下方是严重级别分布条形图，条长按最大档位归一化，颜色对应严重程度（严重红、高危黄、中危蓝、低危灰）。这些数字用于回答「为什么这个包从不命中漏洞」——先看库里到底有没有对应生态与档位的条目。
3. 快照从哪来：公网可直接下载 OSV.dev 的分生态导出（`https://storage.googleapis.com/osv-vulnerabilities/npm/all.zip`、`.../PyPI/all.zip`），它聚合了 GitHub Advisory Database 与 PyPA Advisory Database，是唯一同时覆盖 npm 与 PyPI、且带包名与版本区间的单一来源。OSV 原始格式与本平台导入格式不同，用仓库里的 `npm run vulndb:sync` 转换并分片（导入接口单次上限 50 MB，npm 全量约 23 万条），再加 `--upload` 可直接推到运行实例。NVD 的 CVE JSON 不含包名映射，只适合补 CVSS 分值。
4. 导入完成后建议立即点击「立即全量复检」，对全部已入库版本按新漏洞库回溯扫描；命中隔离阈值的版本会自动置为隔离。
5. 服务端按 `SECURITY_RESCAN_INTERVAL_SEC` 自动执行定期复检（默认开发环境每天一次，测试环境关闭）；复检结果展示在顶部「最近复检」提示中。
6. 复检只在结论或规则命中发生变化时新增记录，避免重复堆积；变化项可在「校验记录」中按触发方式「复检」识别。

> 排版说明：「隔离区待复核」与「漏洞库同步」两张卡片始终等高，底部各有一条分隔线（左侧是分页器，右侧是导入区），两卡的视觉重心落在同一基线上。隔离区表格区限高内滚，条目再多也不会把整张卡拉高。

## 7. 审计日志

1. 进入「审计日志」（仅 admin 可见）。
2. 可按动作关键字（如 `import.batch.commit`、`missing.supplement`）与结果（success / failure）过滤。
3. 列表展示时间、操作者、动作、资源、结果与 traceId，可据此关联服务端日志。
4. 点击「导出 CSV」下载当前过滤条件下的日志；导出文件带 `Content-Disposition`，不受响应信封包装。

## 8. 访问令牌

1. 进入「访问令牌」，输入名称、选择有效期后点击「创建令牌」。创建页只给当前登录账号签发；管理员要给其他账号（尤其机器账号）签发，到「用户管理」点对应行的「签发令牌」（签发弹窗里同样可选有效期）。令牌名建议按仓库命名（如 `ci-group-repo`），会写入审计日志。
2. 令牌仅在创建成功时展示一次，请立即复制保存；服务端只存 SHA256 哈希。弹窗会同时写明到期时间或「永不过期」，便于当场记录轮换计划。
3. 列表展示名称、创建时间、最近使用时间与状态；**有效期显示在状态列下方**——有效令牌标注「YYYY-MM-DD 到期」，剩余 7 天内变为橙色「N 天后到期」，未设期限的标「永不过期」。吊销后的令牌标为「已吊销 · 手动」「已吊销 · 批量」「已吊销 · 管理员」「已吊销 · 过期」，便于事后判断是谁在什么场景下作的废。
4. **有效期**：创建/签发时可选 30 / 60 / 90 / 180 / 365 天或「永不过期」，默认「跟随默认」取服务端 `API_TOKEN_TTL_DAYS`（90 天）。选「永不过期」会先弹风险确认——长期凭据泄露后没有自然失效兜底。到期后令牌立即失效，下一次被使用时会自动标记为「已吊销 · 过期」；升级前签发的存量令牌没有到期时间，按不过期处理，不受影响。
5. **筛选**：顶部可按令牌名（管理员还可按账号名）过滤，并按状态切换「仅有效 / 已过期 / 已吊销 / 全部状态」。**默认只显示有效令牌**——已过期与已吊销的凭据留在库里可查，但不干扰日常视图。标题右侧显示统计（如「共 8 个令牌 · 有效 6 · 已过期 1 · 已吊销 1 ｜ 当前显示 6 个」）。
6. **吊销是破坏性操作**：点击「吊销」会弹二次确认框，明确写出令牌名与「永久作废、无法恢复」，确认后才会执行。
7. CLI 使用方式：`Authorization: Bearer yj_...`，或 npm `_auth` / twine `-u __token__ -p yj_...`。

### 8.1 谁能看到哪些令牌

| 角色 | 可见范围 | 可执行操作 |
| --- | --- | --- |
| 任意登录账号（`token:manage`） | 只有自己的令牌（可按令牌名 + 状态筛选） | 生成、吊销自己的令牌 |
| 管理员（`user:manage`） | 全部账号的令牌，可按账号/令牌名 + 状态筛选，并可切「全部账号 / 仅我的」 | 额外可吊销**任意账号**的令牌，并在「用户管理」按账号批量吊销 |

判定在后端完成：列表默认返回本人令牌；管理员切到「全部账号」时才带 `scope=all` 请求，普通用户带 `scope=all` 一律返回 403 `AUTH_FORBIDDEN`。代吊销的令牌会记为 `revoke_reason=admin_revoke`，审计动作 `auth.token.revoke` 的 `detail.scope` 区分 `self` / `other`，代吊销还会落 `targetUsername`——事后能明确回答「是谁吊销了谁的凭据」。

## 9. 用户管理（管理员）

入口：侧边栏「用户管理」，仅 `admin` 可见（权限点 `user:manage`）。

角色代码只有三个，接口、Excel 模板与界面下拉都以这份为准（旧文档里出现的 `viewer` 已被收敛为 `reader`，接口仍接受该别名并自动转成 `reader`，但非法值不会再被静默降级）：

| 代码 | 中文名 | 关键权限 |
| --- | --- | --- |
| `admin` | 管理员 | 全部权限，含用户/令牌/字典/安全复核；且**全平台唯一**，不可新建、提升、降级或禁用 |
| `developer` | 开发者 | 读包、发布（npm/twine）、批量导入、补缺包、管理自己的令牌、看自己包的安全结论 |
| `reader` | 只读 | 读包、管理自己的令牌（旧名 `viewer`，接口兼容并归一为 `reader`） |

1. **创建账号**：填写用户名（字母/数字/`._-`，3–32 位）、显示名、邮箱，选择账号类型与角色，点击「创建账号」。人员账号初始密码统一为 `123123123`，**只在创建结果中展示一次**，请通过安全渠道转交本人；对方首次登录必须改密。机器账号不设口令，创建后自动进入签发令牌。
2. **管理员账号唯一**：管理员只在系统首启时按 `BOOTSTRAP_ADMIN_*` 创建，用户管理中不提供新建、提升或降级入口。列表里管理员行角色为只读标记、不提供「禁用」；其他账号的角色下拉只有 `reader` / `developer`。服务端同步校验，绕过前端调用接口会被 `SYS_VALIDATION` 拒绝（提示「管理员账号唯一」）。
3. **调整角色**：普通账号的角色下拉（`reader` 只读 / `developer` 可发布与导入）**选中后弹二次确认**，写明角色变化方向与对应权限；取消则下拉自动回退到服务端真实值，不会出现「界面显示已改、实际没改」。失败时给出原因提示并重新拉取。
4. **启用 / 禁用**：点击「禁用 / 启用」先弹二次确认（禁用为危险色，文案说明会话立即失效、令牌暂时不可用但不会作废）。确认后禁用会立即让该账号所有会话失效，令牌也同时不可用（请求返回 `AUTH_UNAUTHENTICATED`），登录返回 `AUTH_USER_DISABLED`。但禁用**不会作废令牌**——凭据仍然保留，重新启用后自动恢复可用。这与主流平台（AWS access key 的 Deactivate/Activate）语义一致，目的是让「临时停用」可以随时回滚。管理员账号不可禁用。
5. **吊销令牌**：需要**永久**断开某个账号的凭据（离职、凭据泄露、项目下线）时，点该行「吊销令牌」，确认后该账号名下所有未吊销令牌立即作废，**不可恢复，重新启用账号也不会复活**，只能重新签发。凭据列会显示每个账号还挂着几个未吊销令牌；账号处于禁用状态时该数字标为橙色，提示「这些令牌只是暂时不可用、仍未作废」。
6. **重置密码**：恢复为该角色固定初始密码（同样只展示一次），旧密码立即失效、失败计数与锁定一并清除，对方下次登录重新进入强制改密流程。机器账号没有可用口令，此按钮不提供，重置接口也会被拒绝（`SYS_VALIDATION`）——给它换令牌即可。
7. **批量建号**：点「下载模板」取得 XLSX；仅支持 `.xlsx`，模板前 5 行是填写须知，从第 6 行表头下方开始填写，单次最多 200 行。角色只接受 `developer` / `reader`，`admin` 行会被逐行拒绝（管理员账号唯一）；批量建号只创建人员账号。
8. **机器账号（CI）**：账号类型选「机器账号」后，账号不设口令、拒绝口令登录（`AUTH_SERVICE_ACCOUNT`），列表带 `CI` 标签、凭据列显示「仅令牌」。创建成功会直接弹出签发令牌窗口；之后也可点该行的「签发令牌」补发。令牌明文只展示一次，请立即写入流水线的密文变量（如 `YJ_TOKEN`）。建议**一个仓库一个机器账号**、令牌名用仓库路径（`ci-group-repo`），这样审计日志可按令牌名筛出该项目。

### 9.1 字典管理（管理员）

入口：侧边栏「字典管理」，仅 `admin` 可见（权限点 `config:manage`）。四组运行时配置，保存后立即生效、无需重启，并写入审计（`config.dictionary.update`）。三角色（console / npm / pypi）是独立进程，但共享同一个 SQLite 库（WAL）：字典覆盖层会按 `DICTIONARY_SYNC_INTERVAL_MS`（默认 1000 毫秒，范围 0–60000，0 表示每次读取都回读）自动回读共享库，因此在控制台里改配置，**全部服务进程都会同步生效**，不需要逐个重启容器；保存方进程本身是零延迟生效。

1. **限流参数**：总开关、窗口长度与认证 / 写入 / 读取三类上限。认证类只统计真正校验凭据的入口（`/api/v1/auth/login`、`/api/v1/auth/change-password`），因此调小认证上限只会影响登录与改密；令牌列表 / 签发 / 吊销、`/auth/me` 等已登录接口按读 / 写配额计数，不会被登录限流误伤。改小窗口后当前窗口内的计数会被重置。
2. **漏洞扫描与校验**：扫描总开关、强制签名、漏洞库未初始化时拦截。关闭扫描后，普通用户侧栏不再显示「安全校验」，批量导入页只保留上传卡并直接入库。
3. **保留与清理**：软删除包可恢复天数（默认 30）与日志文件保留天数（默认 180），填 `0` 表示不自动清理。
4. **包文件备份**：启用开关 + 备份间隔（分钟，1–10080）。开启后按间隔把已入库的包文件增量复制到备份目录（默认 `<DATA_DIR>/backups`，与 `objects/` 同构，可直接按 `<sha 前 2 位>/<sha256>` 找回）。关闭只停止后续备份，**已有备份不会被删除**；备份不参与保留期清理，源包被硬删除后备份仍在。间隔决定时效窗口：60 分钟意味着最近一小时入库的包最坏情况下还没进备份，要更实时就调小；每轮只补齐缺失文件，不改动已有备份。
5. **缺包自动上报**（`missing.autoReport`）：开启后，下游把本平台设为 npm / PyPI 源、拉取包失败时会自动登记缺失依赖（含来源 IP）；关闭只停新增，已有记录保留。显式上报接口始终可用。
6. **上传大小上限**（`limits.maxNpmUploadBytes` / `limits.maxPypiUploadBytes`）：分别限制 npm 解包后与 twine 单文件大小，默认 200 MB，保存后即时生效。硬天花板由环境变量 `MAX_NPM_PUBLISH_BYTES` / `MAX_PYPI_PUBLISH_BYTES` 控制（默认 288 MB，需重启），字典值不可超过它；wheel 走磁盘落盘，不占请求体内存。
7. **签名与漏洞库强制**：`security.requireSignature` 开启后未签名或验签失败按高危处理；`security.requireAdvisoryDb` 开启后本地漏洞库为空按高危处理，避免拿到虚假的 ALLOW。

### 9.2 编辑用户手册（管理员）

1. 进入侧栏「用户手册」，管理员在目录卡片右上角看到「编辑手册」。普通用户只有阅读权限，看不到编辑按钮与工具栏。
2. 点「编辑手册」进入所见即所得编辑：**直接在正文上点击就能改字**，不需要认识 HTML。每节上方会出现排版工具栏：
   - 下拉切换当前段的样式：正文 / 要点提示（绿框）/ 小标题 / 编号步骤 / 项目符号 / 代码块；
   - 「B」加粗（也可 Ctrl+B）、「</>」行内代码、「链接」插入链接、「清除格式」把一段还原成普通正文。
   - 行内代码要选中文字再点，选中范围限同一段落；不选文字直接点会插入一个空代码框，接着输入即可；已经加过代码的文字再点一次即取消。清除格式对代码块是整块降级成正文，对列表项只清行内格式、保留列表结构。
3. 移动光标时工具栏的段落类型会跟着变，可以随时确认当前段是什么样式。有改动时工具栏变黄；点「保存修改」只提交真正改过的章节，没动过的章节不会写入。
4. 粘贴不需要清理格式：从 Markdown 文档复制的内容会自动转成标题、列表、代码块与表格；从网页或 Word 复制的内容会丢掉字体、颜色等噪音，只保留段落与加粗。
5. 「权限」可把某一段限给具备指定权限点的用户（例如发布说明只给 `package:publish` 的人看）。编辑态用左侧虚线 +「限 xxx」标签提示，普通用户看不到这一段。
6. 内容按章节存 SQLite 的 `user_manual` 表；没有保存过的章节继续用内置静态手册。点「恢复默认」会清除全部章节覆盖，回到内置内容，操作前有二次确认。
7. 保存时服务端仍按白名单清洗：保留 `p / h3 / h4 / ol / ul / li / pre / code / b / strong / em / i / small / br / hr / table / thead / tbody / tr / th / td / span / div / a` 与 `class / title / 安全 href / data-manual-perm`；`script`、`iframe`、`svg`、事件属性、`javascript:` 链接会被过滤或转成纯文本。把某节内容全删光时保存会被拦下并提示，避免误当「恢复默认」。
8. 每次保存写审计 `manual.content.update`，记录操作人、时间与变更章节列表；敏感凭据不会出现在审计详情里。

## 10. 错误提示与排查

所有接口失败均返回 `code`、可读 `message`、`traceId`；控制台以 `[CODE] message（traceId: ...）` 形式提示，不会出现无响应空白。

| 错误码 | 含义 | 处理建议 |
| --- | --- | --- |
| `AUTH_UNAUTHENTICATED` | 未登录或会话失效 | 重新登录或检查令牌 |
| `AUTH_INVALID_CREDENTIALS` | 用户名或密码错误 | 核对输入；`details.remainingAttempts` 为剩余可尝试次数 |
| `AUTH_ACCOUNT_LOCKED` | 失败次数过多，账号临时锁定 | 按 `details.retryAfterSec` 等待解锁，或联系管理员重置密码 |
| `AUTH_PASSWORD_CHANGE_REQUIRED` | 首登/重置后未改密 | 完成改密后再访问业务接口 |
| `AUTH_USER_DISABLED` | 账号已被禁用 | 联系管理员启用 |
| `AUTH_FORBIDDEN` | 当前角色无该操作权限 | 联系管理员调整角色 |
| `SYS_CONFLICT` | 用户名等唯一资源冲突 | 换一个用户名 |
| `TARGET_UNDECLARED` | JSON 清单缺少 targets | 补 `targets.node` / `targets.python` |
| `MANIFEST_FORMAT_INVALID` | 清单格式不支持或解析失败 | 检查扩展名与文件内容 |
| `PKG_FILE_UNMATCHED` | 清单条目未匹配到上传文件 | 核对文件名与 `file` 字段 |
| `PKG_VERSION_DUPLICATE` | 版本已存在 | 升级版本号或先删除旧版本 |
| `BATCH_HAS_BLOCKING_ITEMS` | strict 模式存在失败项 | 改用 partial 或修复失败项 |
| `MISSING_STATE_INVALID` | 缺失记录已解决 | 刷新列表，无需重复补包 |
| `SEC_BLOCKED` | 安全校验发现严重风险，包被拦截 | 按返回的 `scanId` 查看报告与整改建议，修复后重新打包上传 |
| `SEC_QUARANTINED` | 安全校验发现高危风险，包被隔离 | 携带 `scanId` 联系管理员复核；确认可信后由管理员放行 |
| `SEC_SCAN_FAILED` | 安全扫描器执行异常（fail-closed） | 稍后重试；持续失败时把 `traceId` 提供给管理员 |
| `SYS_NOT_FOUND` | 接口路径不存在 | 检查 URL 与请求方法 |

需要进一步定位时，把响应中的 `traceId` 提供给管理员，可在审计日志与服务端日志中检索同一请求链路。
